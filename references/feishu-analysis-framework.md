# 飞书交互设计分析框架与显示条件

本框架帮助设计师讲解和评审实际项目，不是强制逐章填写的空表。`必需`表示每篇都回答、简单需求可合并；`条件必需`表示满足触发条件才显示；`可选`表示有证据且能帮助决策时显示。没有触发的章节直接省略，不保留空表。事实、设计建议、推断、待确认和非范围应在相关位置区分。已有文档定点更新，不复制一套框架章节到项目正文。

## 1. 业务背景与业务目标

回答为什么现在做、希望产生什么业务结果。业务问题与需求来源、业务目标、版本定位为**必需**。业务目标描述本期业务结果，例如支持目标场景或补齐交付能力；定量目标需有基线。版本定位由产品／版本规划确定，设计分析引用规划结论并注明来源；规划未给出或相互冲突时标为待确认，不根据需求内容自行判定为体验优化型或市场竞争型。规划明确主次目标时沿用其表述。市场、政策、竞争与产品战略等核心驱动因素，以及商业／产品价值通常为**可选**；仅在解释业务目标或设计取舍时展开相应证据。开篇保持短，范围与待决策随方案展开。

## 2. 目标用户、任务与现状体验

实际使用角色、结果导向的 JOB、具体 Case、现状路径与主要断点、融入体验诉求的业务／产品目标及由其推导的设计目标为**必需**。每个 Case 关联业务结果，并将该场景中角色期望改善的理解、预期、负担或恢复体验融入同一条业务／产品目标，不另列“体验目标”；再由该综合目标形成设计重点与设计目标。设计目标在同一句中写明场景、角色、关键设计手段及预期体验改善。手段表达支撑改善的机制，不把产品指标、详细设计策略、具体界面动作或验收步骤直接当成目标，也不编造用户情绪。每个 Case 说明前提、可观察的完成标识，以及设计目标如何回应综合目标中的业务结果和体验诉求。能够基于可靠基线和一致统计口径量化时，补充指标、目标值、测量方式与周期；暂不可量化时使用可观察的行为与结果标准，不编造数字。目标客户行业、规模等画像为**可选**；现有系统、资源、术语、操作习惯、协作方式和迁移约束在影响任务或设计时为**条件必需**。任务跨阶段／角色／触点且有交接断点时，现状—目标旅程为**条件必需**。异常路径合并到对应 Case，写明触发条件、用户可见反馈、可执行操作、恢复或退出路径及恢复后的完成标识，不另建异常 Case。情绪、耗时和满意度仅在有研究或测量证据时**可选**，不得编造。

当规划将体验优化列为本期目标时，受影响 Case 的深入体验分析为**条件必需**：还原用户从入口到完成／恢复的关键动作和判断；用访谈、观察、日志、反馈或可复核的现网证据定位理解、效率、反馈、交接、容错等实际断点，说明影响的人群、频次或严重程度（有据可查时）；区分已证实成因与待验证假设，按用户影响和业务目标确定改进优先级；写清目标体验、设计机会与验证方法。只展开与该任务相关的维度，不用无依据的情绪曲线或数字填充。单页任务可用逐步任务分析，不强制绘制跨角色旅程。

## 3. 竞品参考与设计取舍

本章为**条件必需**：用户明确要求研究，或重要未知项与风险会影响对象、入口、流程、配置暴露、状态恢复、权限或安全时展示。展示后，研究问题、同任务的操作／反馈／交接／恢复证据、竞品功能体验评分及其证据可信度、差异原因与适用条件、我方取舍及验证均为必需；资料只覆盖局部流程时明确评分范围和缺口。完整操作记录与截图集**可选**放附录。不能将竞品能力说明当成界面易用性或我方体验已验证的证据。

## 4. 本期整体方案与范围

整体方案、本期设计覆盖、信息架构与入口为**必需**；入口缺少平台证据时停留在候选层。易误解的非范围、多对象关系影响理解、落地障碍改变任务或交互、分期改变操作／协作方式时分别为**条件必需**。障碍按“障碍 → 受影响任务 → 设计处理 → 剩余限制”收敛：现状断点归旅程，未确认依赖归待决策。分期需说本期如何完成、哪些需人工、后续会改变什么，不将未来能力画成现状。重要方案分歧与选择理由**可选**；不为凑章节编造分期或量化收益。

## 5. 核心流程、页面与交互

主任务路径、页面职责与信息优先级、入口操作和结果反馈为**必需**。流程节点数量由实际页面／状态变化、关键判断、角色交接与完成结果决定，不按模板固定步数；普通字段操作不机械拆分。存在相应情况时，分支／回退／中断恢复、字段校验、跨角色或跨系统交接、影响判断与恢复的关键文案为**条件必需**。失败分支应接在触发它的主路径步骤上，写清条件、反馈、下一步和返回位置，不另画脱离上下文的统一失败流程。所选交付模式包含线框时，页面线框为**条件必需**。旅程解释业务协作，页面流程解释页面跳转；图承载布局，配套说明承载交互规则，避免重复罗列。

## 6. 状态、权限与异常恢复

关键状态及可操作性为**必需**。加载／空态／失败、权限差异、高影响操作、失败恢复、并发冲突和直接改变交互的安全合规要求，在存在相应风险时为**条件必需**。说明用户可见的影响、允许操作、反馈与下一步。简单需求可并入对应页面；跨页面规则集中维护，Case 级异常不能仅由状态表替代。

## 7. 待决策事项

存在会改变当前方案的未决问题时，本章为**条件必需**。每项包含问题、受影响的任务／页面／状态／权限、当前假设或建议、确认依据与参与角色、确认前处理方式。影响当前页面理解的假设还须就地简短标注；不把假设写成已确认业务规则，也不把未指派角色写成责任人。

## 8. 设计验收与价值验证

Case 完成性、设计目标与综合业务／产品目标的契合验证、业务目标验证为**必需**。业务目标记录达成依据与设计可验证的部分，不用原型声称真实业务结果已达成。异常／权限／高风险验收及验证限制在相应情况时为**条件必需**，并回到对应 Case 的异常路径验收。能够基于可靠数据量化时，指标、基线、目标值、统计口径、测量方式与周期为**必需**；缺少可靠基线时用可观察的任务行为与结果标准验证体验，不编造成本、效率或成功率。规划包含体验优化目标时，逐个受影响 Case 对照现状断点与目标体验，验证用户能否更顺利地完成任务；没有基线时说明先如何建立基线。用短引用保持“业务／产品目标（含体验诉求）→ 设计目标 → Case／阶段 → 设计策略 → 页面／验收”可追踪，不另建重复大表。

## 附录与表达

关键结论的来源标注为**必需**；独立附录**可选**，用于完整操作记录、详细追踪和辅助技术资料。飞书原生表格适合多字段映射，白板适合阶段交接、分支、层级和对象关系；简单线性内容用段落。只在图能提高决策效率时使用，不强制每篇配齐所有组件。粘贴表格后检查实际单元格内容及正文显示宽度，避免空表、重复表、狭窄说明列和不可读的长文本；新内容验证可读后再移除被替代组件。
