# 输入与证据边界

## 输入清单

| 输入 | 必需性 | 使用方式 |
|---|---|---|
| PRD、需求描述或截图 | 至少一种 | 提取问题、目标、规则、角色和范围 |
| 现有平台页面、Workspace 或截图 | 可选 | 提供后必须核查入口、布局和交互惯例 |
| 飞书目标链接 | 同步时必需 | 写入前先读取，不把空白假设成事实 |
| 输出目录或命名要求 | 可选 | 缺省写入当前工作区 `output/<topic>/` |

## 证据等级

- 已确认事实：来自用户明确确认、PRD 或可验证产品证据。
- 设计决策：在已确认约束下作出的可评审方案。
- 设计推断：证据不完整但可逆，必须记录依据和核查动作。
- 待确认：会改变业务、权限、安全、不可逆影响或实现范围。
- 非范围：本期明确不生成入口、页面或操作。

输入中的解决方案不是天然事实。先还原问题、用户结果和硬约束，再决定是否采用。来源冲突时保留冲突，不自行选择一方。

## 平台输入规则

平台证据不是开始分析的硬门槛。未提供时可以分析 Job、对象、规则和风险，但不能把导航、页面归属或组件形态写成确定结论。用户提供平台链接、截图或 Workspace 后必须参考，不能只依据通用后台模板重新设计。
