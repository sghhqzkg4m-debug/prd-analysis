# 交付物约定

## 输出组合

| 场景 | 默认最终交付 |
|---|---|
| 无飞书目标，分析需求文件 | 自包含 HTML；需要线框时嵌入线框与必要图表 |
| 用户明确要求仅文本分析、仅聊天答复或仅 Markdown | 对话内结论或 Markdown |
| 有飞书目标，未要求 AI 生成页面 | 完整飞书设计文档 |
| 有飞书目标，要求 AI 生成页面 | 完整飞书设计文档 + `<topic>-ui-generation-spec.md` |
| 用户明确要求本地源文件 | 在上述基础上增加所需工作文件 |

没有飞书链接不构成交付阻塞，也不需要先向用户索取链接。分析需求文件且用户未指定其他交付格式时，HTML 直接作为默认主交付；分析 Markdown、图源和校验文件默认作为工作文件保留。有飞书目标时，HTML 不作为并列最终交付；只有飞书不可写、用户明确要求或需要临时评审载体时才生成。

## 工作目录

```text
output/<topic>/
├── <topic>-交互设计需求分析.md
├── <topic>-飞书同步稿.md
├── <topic>-ui-generation-spec.md
├── wireframe-*.svg
├── wireframe-*.png
├── flow-*.svg
├── flow-*.png
└── diagram-*.svg / diagram-*.png
```

同一主题后续更新原文件，不创建 `v2`、`final2` 等副本。飞书同步稿只在 `feishu-delivery` 或 `full-ui-handoff` 生成；UI 规格只在 `full-ui-handoff` 生成。

分析 Markdown、同步稿、SVG、PNG、预览和校验文件可以作为过程产物存在，但不自动出现在最终交付清单中。

## HTML 设计文档

HTML 是没有飞书目标时的可浏览设计主交付，需满足以下契约：

- 默认使用单文件自包含形式，内嵌 CSS、SVG 和必要脚本；外部资源必须稳定可访问，或与 HTML 放在同一交付目录。
- 用户未提供模板时，从 `assets/sangfor-feishu-analysis-template.html` 原文件生成项目 HTML，逐槽位替换内容；保留九章标题、顺序、目录锚点、主要组件归属、CSS 和交互脚本。只在原组件内增补项目行、Case 或文本，并按证据裁剪模板明确标记的条件内容；用户模板优先于该内置资产，且同样保留其内容框架，除非用户明确要求改版。
- 叙事主线与飞书设计文档一致：业务问题、业务目标与版本定位 → 用户／JOB／Case 的综合业务／产品目标与设计目标推导 → 竞品取舍（触发时）→ 整体方案与信息架构 → 页面流程与草图 → 状态、权限和异常恢复 → 待决策 → 验证与依据。
- 只展开已触发的条件维度和可选维度；没有证据的客户特征、收益、分期或竞品分析不填充虚构内容。固定章节仍保留原位，以一句适用性说明交代未触发原因，不留下空表或模板占位。
- 用户旅程、信息架构和页面流程优先使用图形化表达；流程有分支、回退或跨角色交接时，必须显式绘制连接关系。不同 Case 的路径不同则分别展示。现状用户旅程的 HTML 结构、占位提示和连线规则统一遵循 [html-current-journey.md](html-current-journey.md)，并保留“阶段分组—子阶段／动作列—角色动作编号—所想—痛点—用户需求—设计点子—验证证据”的逐动作追踪关系。
- `analysis-with-wireframe` 或内容已进入页面方案时，HTML 内嵌关键页面草图，并标明载体、主要区域、关键状态与交互反馈。
- 提供可靠目录与锚点；来源链接靠近对应结论；窄屏允许图表容器局部滚动，但正文页面不得整体横向溢出。
- 用户提供模板时继承其章节与组件框架、视觉规范和品牌元素，保留 Logo 的正确比例与留白；不自行重组章节或把模板降级为视觉参考。
- 同一主题后续修改原 HTML。最终回复提供该文件的可点击绝对路径，并准确说明是否已同步飞书。
- 聚焦竞品研究需要完整证据记录时，可在同一目录增加独立自包含的竞品研究详报 HTML。主 HTML 保留关键比较与取舍并以相对链接进入详报；详报提供返回主文的链接、来源与核查日期、任务对照、逐维评分或未评分原因、证据缺口及验证计划。两页使用同一组结论，不把详报误称为已有真实用户测试的完整体验报告。

## 设计结论集

按风险裁剪，但通常覆盖：设计结论；当前问题、本期目标和用户价值；按 Case 将体验诉求融入业务／产品目标并推导设计目标；证据、范围和待确认；用户、场景与 Job；信息架构与核心对象；流程和恢复；页面与线框；状态、权限和安全；平台继承；验收和阻塞。

## AI 页面生成规格

必须自包含并可执行，至少包括页面与载体清单、页面契约、组件树、字段规则、状态矩阵、权限、安全、Mock 数据、允许与禁止修改、实现顺序、验收和阻塞项。不得把尚未确认的组件名、API 或业务规则写成事实。

UI spec 承接飞书正文不适合展开的实现级内容，包括组件语义、字段校验、Mock、路由/文件计划、允许与禁止修改、实现顺序、接口核查动作和自动验收。它可以深化实现表达，但不得新增业务决定。

## 飞书设计文档

是面向产品、设计、研发共同评审的设计主交付。它应突出用户任务、结构决策、页面行为、状态、权限、异常恢复、文案和设计验收，而不是后端架构说明书。原生白板必须在写入阶段创建和填充。文档不得包含工具说明、文件路径、授权过程或面向操作者的元指令。
